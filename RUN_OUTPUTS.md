# Batch run format (version 1)

Each run has its own folder. The Colab notebook creates one under
`outputs/batches/<timestamp>/`. The mask method does not change the layout.

```text
<run>/
  cases.json
  results.json
  timings.json
  batch.log                  # when launched through the notebook
  masks/
    000048_000001_obj_000001_mask.npy
  000048_000001_obj_000001/
    pose_000048_000001_obj_000001.npy
  evaluation.csv             # generated by evaluate_batch.py
```

`cases.json` records the selected object/frame cases. Each `results.json` entry
contains `folder_id`, `image_id`, `object_id`, `status` (`ok` or `failed`),
`pose_path`, `mask_path`, mask provenance, and available timings. Failed entries
include an `error`; missing paths are null. Paths are relative to the run folder.
`timings.json` contains `format_version: 1`, mask provenance, setup and runtime
measurements, and success/failure counts. New mask implementations should keep
these fields and use `mask_source` to identify the method.

Each pose is a 4-by-4 NumPy array containing the object-to-camera transform,
with translation in meters. Each saved mask is a boolean NumPy array matching
the depth image dimensions.

To launch a batch, pass `--cases-file <selection.json>` and `--run-dir <new-run>`
to `src/run_batch.py`. The runner saves its own normalized case list. Existing
results are protected from overwriting; use a new run folder for another attempt.

To evaluate a standard run, pass only `--run-dir <run>` to
`src/evaluate_batch.py`. The evaluator writes `evaluation.csv` into that folder;
it reads the YCB reference poses from the project's dataset. The run folder may
be downloaded, moved, or renamed without changing the saved relative paths.
The notebook ZIP contains this same layout, including masks.

CSV columns are `folder_id`, `image_id`, `object_id`, `rotation_error_deg`, and
`translation_error_mm`. Compare runs using the three ID columns and the same
selected cases. All selected poses must exist for evaluation to complete;
failed or incomplete runs are not silently scored using only their successes.

The older `--results-file` and `--output-root` runner options remain available
for compatibility. `--output-root` opts out of the default pose layout. For older
downloaded runs whose poses are nested elsewhere, the evaluator's `--pose-root`
option selects that location. Existing historical folders are not migrated.
